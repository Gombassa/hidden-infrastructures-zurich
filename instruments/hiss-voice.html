Feeder identity here is _dedupKey (a per-point coordinate hash baked in at extraction time, in lk-tram-lk.geojson) — not the objectid the manual field above implies, since tram nodes don't carry that property. _dedupKey stays stable across GeoShop re-extraction, unlike ProximityEngine's own feeder id (an array index). It is used only to match live position against the feeder set and is never written to the downloaded log — only the derived seed is, since the key itself encodes the feeder's coordinates. Default radius is 50 m as specified; production's actual hiss-trigger radius (FEEDER_HISS_RADIUS in audio-layers.js) is 25 m, so voices left at 50 m may spawn near-silent until under ~25 m. Bearing-driven HRTF positioning is deliberately not wired in this pass — this walk is for the voice model and allocation policy first; positioning is next.
