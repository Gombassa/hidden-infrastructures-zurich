That identity is internal to the synth and never leaves this page — the exported log still carries only random per-voice tokens unrelated to it. Two LFOs on separate rates modulate comb delay and filter cutoff. A 600 Hz tone sits under the noise: 50 Hz mains through 12-pulse rectification. Positioning is real HRTF now, not the hashed stereo pan this page used to demonstrate.

Feeder identity here is _dedupKey (a per-point coordinate hash baked in at extraction time, in lk-tram-lk.geojson) — not the objectid the manual field above used to imply, since tram nodes don't carry that property. _dedupKey stays stable across GeoShop re-extraction (verified by re-extracting one order in isolation and diffing keys), unlike ProximityEngine's own feeder id (an array index). It is used only to match live position against the feeder set. Neither the key nor the timbre seed derived from it is ever written to the log — the feeder set is small (~2,100 nodes) and public, so a logged seed could be reverse-matched against every feeder's hash and the walk reconstructed. Each voice instead gets a random log token and replay seed, generated fresh at spawn, with no relationship to the feeder. Radius is fixed at 25 m now — TramHissPool hardcodes production's actual FEEDER_HISS_RADIUS internally, matching this page's earlier finding that the old 50m default spawned voices too far out to be audible. Bearing-driven HRTF positioning, previously deferred, is wired in as of Step 4.
